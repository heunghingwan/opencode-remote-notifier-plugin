## OVERVIEW

OpenCode plugin that forwards session events (errors, permission requests, questions, idle) as push notifications via ntfy.sh. Single-file TypeScript, no build step.

## CONVENTIONS

- **No build step**: TypeScript loaded directly by OpenCode/Bun. No tsconfig, no compilation.
- **Single-file architecture**: All logic (config, rate limiting, HTTP, event routing) lives in one file. No module separation.
- **npm publishing wrapper**: Root `package.json` is publish metadata; `.opencode/` holds runtime deps.
- **Config via XDG path**: Not environment variables — reads `~/.config/opencode/remote-notifier.json`.
- **Events only**: Plugin implements only the `event` hook — no `tool`, `command`, or other hooks.
- **Module-level mutable state**: Session tracking maps are global across events (no explicit lifecycle).

## ANTI-PATTERNS (THIS PROJECT)

- **No tests**: Zero test infrastructure. Event routing logic is untested.
- **No typechecking**: No `tsconfig.json`, no `tsc` — type errors surface only at runtime.
- **No linting/formatting**: No ESLint, Prettier, or EditorConfig.
- **No CI/CD**: No automated checks on push. No release workflow.

## COMMANDS

No npm scripts, no Makefile, no CI — the project has zero automation commands. OpenCode auto-installs via `opencode.json` plugin entry.

## NOTES

- The `.opencode/.gitignore` intentionally excludes `package.json` and lock files — they're regenerated by OpenCode on install.
- Plugin is loaded as TypeScript source; OpenCode's runtime (Bun) handles transpilation.
- Two npm lockfiles exist: root `package-lock.json` (publishing) and `.opencode/package-lock.json` (runtime deps).
